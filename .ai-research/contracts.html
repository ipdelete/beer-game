Cross-Issue Contracts

The small set of decisions that must stay consistent across issues. Everything else is the implementer's call. If you need to change something here, edit this file and ping the issues that depend on it.

What this is. A reference, not a spec. It pins names, formats, and shapes that two independent implementers would otherwise disagree on (column names, seed semantics, CLI verbs). Concrete code, error handling, and internal structure are not contracts — those live in the PR.

1. Bundle layout

A run produces a directory bundle. Inspect AI's .eval ZIP packaging is a future option; for v1 we use a directory.

runs/2026-05-19T14-03-22_qwen2.5-14b/
  manifest.json        # one object: run-level metadata
  games.jsonl          # one line per game (scenario × model × epoch)
  decisions.parquet    # one row per LLM decision call
  states.parquet       # one row per (game, week, position)

manifest.json (required keys)

  • run_id, started_at, finished_at (ISO-8601 UTC)
  • run_seed (int) — top-level seed; per-game seeds derive from it
  • prompt_version (string hash of prompt template files)
  • config (object — fully resolved post-import/merge YAML)
  • config_hash (string)
  • tool_versions (object — python, beer-game, key deps)

games.jsonl (one object per line)

  • game_id, scenario_id, model, epoch
  • demand_seed, llm_seed — see Seeds
  • demand_hash — md5 of the materialized demand array (audit trail)
  • scenario_params_hash — md5 of resolved scenario params dict
  • release_date — see Date conventions
  • started_at, finished_at, error (null on success)

decisions.parquet (one row per LLM call)

Column names come from the OTEL_TO_COLUMN table; that's the single mapping point. Mandatory columns include: game_id, week, position, model, prompt_tokens, completion_tokens, total_tokens, latency_ms, raw_response, parsed_order, parse_strategy, error.

states.parquet (one row per game/week/position)

Columns: game_id, week, position, inventory, backlog, orders_placed, orders_received, shipments_in, shipments_out, cost_this_week, cumulative_cost, customer_demand (retailer rows only; null elsewhere).

2. Seeds

Two seeds per game, derived from one top-level run_seed:

NameScopeDerivationUsed for
run_seedper runrandom or --seed Nroot for everything below; logged in manifest.json
demand_seedper (scenario, epoch)stable_hash((run_seed, scenario_id, scenario_seed, epoch)) % 2**32seeds the demand-pattern PRNG. Model-independent — same value across all models for the same (scenario, epoch). Required for paired bootstrap.
llm_seedper (scenario, model, epoch)stable_hash((run_seed, scenario_id, model, epoch)) % 2**32sent as gen_ai.request.seed to the LLM. Model-specific. Honored by Ollama, vLLM; ignored by some APIs.

Both per-game seeds are logged in games.jsonl.

3. CLI surface

bench run     --config <path> [--scenarios ...] [--models ...]
              [--epochs N] [--seed N] [--parallel N]
              [--no-cache] [--refresh-cache] [-o <bundle-dir>]

bench list    <bundle> [--sort <metric>] [--scenarios ...] [--models ...]
              [--release-after YYYY-Qn] [--format table|json]

bench report  <bundle> [--metrics m1,m2,...] [--format md|html|json]

bench compare <bundle> --baseline <model> --challenger <model>
              [--metric <name>] [--alpha 0.05] [--num-samples 10000]

Verb names and required-flag shapes are contracts. Optional flags can grow.

4. OTel attributes → Parquet columns

Beer-game emits OpenTelemetry GenAI-spec attributes during decisions. A single ParquetSpanProcessor.on_end() is the sole translator from span attributes to Parquet column names via the OTEL_TO_COLUMN table. Nothing else writes Parquet rows directly.

OTel attributeParquet column
gen_ai.request.modelmodel
gen_ai.request.temperaturetemperature
gen_ai.request.seedllm_seed
gen_ai.usage.input_tokensprompt_tokens
gen_ai.usage.output_tokenscompletion_tokens
gen_ai.response.finish_reasonsfinish_reason
beergame.game_id (custom)game_id
beergame.week (custom)week
beergame.position (custom)position
beergame.parsed_order (custom)parsed_order
beergame.parse_strategy (custom)parse_strategy

total_tokens, latency_ms, raw_response are derived in the processor, not direct OTel attrs.

5. Date and version conventions

  • Scenario release date. Format: YYYY-Qn (e.g., "2026-Q2"). Sortable via (year, quarter). Matches LiveBench's quarterly cadence. --release-after uses this format.
  • Timestamps. ISO-8601 UTC with seconds precision (2026-05-19T14:03:22Z).
  • prompt_version. Stable hash (sha256, first 12 chars) of the concatenated content of all prompt template files. Cache invalidates when this changes.
  • scenario_params_hash. md5 of json.dumps(resolved_params, sort_keys=True). Cache invalidates when this changes.
  • config_hash. md5 of fully resolved config, post-import and post-merge. Stable across import-order-equivalent configs.

6. Metric registry

A metric is a function decorated with @metric that takes a bundle and returns a value (scalar, or per-group dict). The registry is the single source of truth for what bench list --sort X and bench report --metrics X,Y recognize.

  • Built-in metrics at minimum: total_cost, service_level, bullwhip_ratio, mean_with_stderr (Inspect-style bootstrap).
  • New metrics: add one decorated function; nothing else changes.
  • bootstrap_stderr uses np.std(..., ddof=0) to match Inspect AI's reference implementation — do not change without changing this contract.

7. Response cache key

The cache key includes all of these. Omitting any field causes correctness bugs (stale replay across prompt/scenario/seed changes).

  • base_url, model
  • temperature, top_p, llm_seed
  • messages (full OpenAI message list, including system prompt content)
  • scenario_id, scenario_params_hash
  • demand_hash
  • prompt_version
  • epoch

8. Config file merge policy

  • Three reserved keys: import: (recursive include), default: (applied before per-key values), overwrite: (applied after, always wins). Pattern lifted from AgentBench.
  • deep_merge recurses dicts and concatenates lists by default.
  • To replace a list instead of concat, add a sibling key _list_policy: {list_key: replace}. _list_policy is stripped from the resolved config.
