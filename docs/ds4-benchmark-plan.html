Current Architecture

Beer Game

Language: Python 3.13 · Package manager: uv · LLM client: openai SDK

The simulation engine (src/engine/simulation.py) runs a Sterman-accurate 4-tier supply chain. Each week, 4 LLM calls are made — one per role — via a pluggable decision_fn(PlayerView) → int.

ComponentPathPurpose
Enginesrc/engine/Simulation loop, state, CSV export
Mechanistic agentsrc/mechanistic/agent.pySterman anchor-and-adjust (baseline: $3,128)
GABM agentsrc/gabm/agent.pyLLM-backed decisions via OpenAI-compat API
Tournament harnessscripts/tournament.shSequential model evaluation, TSV summary
Preflightscripts/preflight.pyOne-shot decode sanity check per model

Key env vars:

  • LLM_ENDPOINT — base URL (default: http://localhost:11434/v1, i.e. Ollama)
  • LLM_MODEL — model name (default: mistral:latest)

ds4

Language: C99 + Objective-C (Metal) · Build: make · Platform: macOS only (Metal-backed inference)

A DeepSeek V4 Flash-specific inference engine. Single-model, single-session, Metal graph execution. The ds4-server binary exposes an OpenAI-compatible HTTP API on port 8000.

EndpointCompatibility
POST /v1/chat/completionsOpenAI — messages, tools, streaming, sampling params
POST /v1/completionsOpenAI completions
POST /v1/messagesAnthropic-compatible
GET /v1/modelsModel listing

Model weights: Custom GGUF from antirez/deepseek-v4-gguf on HuggingFace. q2 quant ≈ 81 GB (128 GB machines), q4 for ≥ 256 GB machines.

Model name in API: deepseek-v4-flash

Proposed ds4 Integration

The integration is zero code change to the simulation engine. The GABM agent already speaks OpenAI-compatible HTTP. ds4-server already serves that API. The only work is:

  1. Build ds4 and download weights on the Mac Studio
  2. Start ds4-server
  3. Point Beer Game at it via env vars
  4. Extend the tournament script to include a ds4 entry

Commands to Run

1. Build ds4 (on Mac Studio)

cd /path/to/ds4
make

2. Download model weights

# q2 for 128 GB machines, q4 for ≥ 256 GB
./download_model.sh q2
./download_model.sh q4

3. Start ds4-server

# q2 variant
./ds4-server -m gguf/deepseek-v4-flash-q2.gguf --ctx 32768 --nothink

# q4 variant
./ds4-server -m gguf/deepseek-v4-flash-q4.gguf --ctx 32768 --nothink

# With thinking enabled (omit --nothink)
./ds4-server -m gguf/deepseek-v4-flash-q2.gguf --ctx 32768

4. Run Beer Game against ds4

cd /path/to/beer-game

# Single run
export LLM_ENDPOINT="http://localhost:8000/v1"
export LLM_MODEL="deepseek-v4-flash"
export PYTHONPATH=.
uv run src/main.py --mode gabm --turns 36 --output results_ds4_q2_nothink.csv

5. Preflight check (recommended)

# Verify ds4 returns parseable integers before a full 36-week run
export LLM_ENDPOINT="http://localhost:8000/v1"
export LLM_MODEL="deepseek-v4-flash"
PYTHONPATH=. uv run python scripts/preflight.py

⚠ The preflight script hardcodes the Ollama model roster. For ds4, either modify the script to accept LLM_MODEL or run the GABM agent manually for a single-decode test.

GABM Agent Compatibility Analysis

The GABM agent (src/gabm/agent.py) has a 3-tier answer extraction strategy:

  1. If </think> in content → take first integer after the closing tag
  2. Otherwise → take the first integer in content
  3. Fallback → last integer in the reasoning field (OpenAI extended)

DeepSeek V4 Flash behavior

ds4-server streams thinking content differently depending on API shape:

  • OpenAI /v1/chat/completions: Reasoning is streamed in the native API shape (likely in content with <think>...</think> tags, similar to Qwen3/Gemma4).
  • The existing </think> parser in the GABM agent should work correctly.

VERIFY Run the preflight to confirm. If ds4 puts thinking in a separate field instead of inline tags, the parser's fallback (strategy #3) should still handle it. If the content comes back empty with reasoning in a different location, we may need a small parser tweak.

Risks & Open Questions

#RiskImpactMitigation
1 macOS-only — ds4 requires Metal. Cannot build or run on Windows. All benchmark work must happen on the Mac Studio. SSH/remote session to Mac Studio, or run locally there. This plan was written on Windows; execution is Mac-only.
2 Thinking format unknown — ds4-server may format thinking differently than Ollama models. Answer parser could extract wrong integer → corrupted results. Preflight check (step 3). If format differs, adapt parser with ds4-specific handling.
3 Model weight download is large — q2 ≈ 81 GB, q4 even larger. Hours-long download depending on connection speed. Start download first; it's resumable (curl -C -).
4 Single-session server — ds4-server serializes inference. Only one request at a time. No impact — Beer Game is already sequential (one call per role per week). None needed. Architecture match.
5 Apples vs oranges — ds4 runs DeepSeek V4 Flash (284B MoE, q2/q4) against much smaller dense models (4–13 GB). Not a fair "model size" comparison. But: the benchmark question is "does it play beer game well?", not "parameter efficiency". Frame results clearly. ds4 is a different class. The interesting question is whether local 284B MoE with aggressive quantization beats smaller dense models on a quantitative task.
6 Temperature / sampling — Beer Game uses temperature=0.4. ds4-server supports temperature, top_p, top_k, min_p, seed. Need to confirm the openai SDK passes these through correctly to ds4-server. Preflight check validates this implicitly.
7 Timeout — GABM agent sets timeout=60 seconds per call. ds4 prefill may be slower for first call (weight loading). First call might timeout if the model isn't warm. Warm up the server with a test prompt before running the benchmark.

Recommended First Implementation Task

Build ds4 + preflight validation

On the Mac Studio:

  1. Clone ds4 (if not already): git clone https://github.com/antirez/ds4.git
  2. Build: make
  3. Download q2 weights: ./download_model.sh q2
  4. Smoke-test CLI: ./ds4 -p "What is 2+2?" --nothink --ctx 4096 -n 32
  5. Start server: ./ds4-server --ctx 32768 --nothink
  6. Test with curl: 
    curl http://localhost:8000/v1/chat/completions \
  -H 'Content-Type: application/json' \
  -d '{"model":"deepseek-v4-flash",
       "messages":[{"role":"user","content":"Reply with only the number 42."}],
       "temperature":0.4, "max_tokens":32}'
  7. Run Beer Game preflight: 
    cd /path/to/beer-game
export LLM_ENDPOINT="http://localhost:8000/v1"
export LLM_MODEL="deepseek-v4-flash"
PYTHONPATH=. uv run python scripts/preflight.py

Success criteria: ds4 returns a parseable integer from the GABM agent's mid-game Wholesaler prompt. If it works, proceed directly to a full 36-week run.
