Fairness pins

Every knob that can move quality or speed is held still and published. Cache keys include these fields, so a change invalidates prior results rather than silently mixing them.

  • max_tokens = 16384Across all three LLMs — same headroom for reasoning + JSON output
  • reasoning_effort = mediumFor models that expose it (gpt-oss, ds4, gemma4 via extra_body)
  • temperature = 0Greedy decoding for reproducibility
  • FLASH_ATTENTION=1Ollama flash-attention enabled
  • KV_CACHE_TYPE=q8_0Ollama 8-bit KV cache
  • NUM_PARALLEL=1Single in-flight request per model — no batching contention
  • KEEP_ALIVE=15mAvoid cold-start variance between roles
  • weeks=36, epochs=1Same scenario shape for every contender
Known asymmetries. "medium" reasoning is not vendor-calibrated; KV cache strategies differ between Ollama and ds4-server; the inference engines themselves are different. We publish the full config rather than claim parity.

How to reproduce

All config lives in the repo. From a fresh clone:

# 1. Bring up tuned ollama + ds4 servers (single-tenant)
scripts/start-ollama.sh
scripts/start-ds4.sh

# 2. Run the full bench pass — mechanistic + 3 LLMs, serial
scripts/single-tenant-bench.sh

# 3. Stop the servers
scripts/stop-ds4.sh
scripts/stop-ollama.sh

Per-contender configs: configs/runs/{mechanistic-baseline,gemma4-e4b,gpt-oss-20b,ds4}.yaml. Model configs: configs/models/*.yaml. See the README for prerequisites (Ollama models pulled, ds4 built from current source).
